# 01 — Déplacements: carburant, véhicules électriques и гео-стек

Запрос пользователя от **2026-07-30**. Документ фиксирует, что надо изменить в
симуляторе «Trouver mon job», и какой геостек для этого выбран.

**Состояние на 2026-07-30, после реализации:**

| Требование                                          | Статус                                                           |
| --------------------------------------------------- | ---------------------------------------------------------------- |
| A — топливо и для работы, и для покупок             | ✅ было сделано ранее                                            |
| C — электромобили                                   | ✅ **сделано** (см. §4 и «что вышло» ниже)                       |
| B — реальные маршруты вместо заглушек               | ⛔ **не сделано:** нужен self-hosted GraphHopper/Nominatim + ETL |
| B — цена литра по станциям, а не средняя по городу  | ⛔ **не сделано:** нужен ETL датасета prix-carburants            |
| Геостек (MapLibre/GraphHopper/OTP/Nominatim/Google) | ⛔ **не подключён:** нужны инстансы и ключи                      |

Почему B и стек не сделаны: у движка нет права ходить в сеть (см. §7), а
маршрутизация требует поднятого сервиса. Как только будет инстанс GraphHopper
(или ключ платного Directions API) и Nominatim — заглушки `distanceToJobKm` и
`distanceToGroceryKm` заменяются на расчёт, и никакие правки в самом движке не
нужны: он уже принимает километры извне.

Связанные документы: `docs/reste-a-vivre-variables.md` (каталог переменных),
`docs/data-catalog.md` (политика данных), `docs/simulateurs-roadmap.md` (долги).

## 2. Что уже есть — чтобы не переделывать сделанное

`src/domain/reste-a-vivre/engine.ts`:

- Километры двух назначений считаются раздельно, а потом **складываются** до
  применения цены за км, поэтому одна машина не тарифицируется дважды:
  `carKm = (commute по авто ? commuteMonthlyKm : 0) + (courses по авто ? groceryMonthlyKm : 0)`.
- `commuteMonthlyKm = km × 2 × (jours/semaine × 45 недель ÷ 12)`.
- `groceryMonthlyKm = distanceToGroceryKm × 2 × tripsPerMonth`.
- Две отдельные строки: `carburant` (статус `computed`) и `usage_vehicule`
  (статус `convention`, 0,15 €/км из барème kilométrique DGFiP).

Значит требование **A закрыто**. Остальное — ниже.

## 3. Требование B — расстояние и цена должны быть настоящими

### 3.1 Расстояние

| Где             | Сейчас                                                                                      | Должно быть                                                  |
| --------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Своя сторона    | `oneWayKm`, введённое пользователем — это факт                                              | оставить как есть (это самая надёжная цифра)                 |
| Целевая сторона | `district.distanceToJobKm` = расстояние **до центра города**, заглушка вместо маршрутизации | адрес работы → маршрут GraphHopper                           |
| До магазина     | `distanceToGroceryKm`, заглушка по кварталу                                                 | BPE (commerce alimentaire) → ближайший → маршрут GraphHopper |

Сейчас в источниках это признано честно: `ban_itineraire.caveat` говорит, что
«distances de cette version sont des distances de référence par quartier, pas
encore un itinéraire adresse à adresse». После внедрения GraphHopper этот caveat
надо переписать, иначе он начнёт врать в обратную сторону.

### 3.2 Цена литра

Сейчас `fuelPricePerLitre` — **одно среднее число на город**. Датасет
prix-carburants при этом даёт цену **по каждой станции** (`geoLevel: "point"`,
обновление раз в 10 минут). То есть мы теряем разрешение, которое у данных есть.

Надо: медиана станций в радиусе N км от жилья (или вдоль маршрута), а не среднее
по городу. Радиус — параметр, который надо зафиксировать и показать пользователю.

⚠️ Осторожно с «актуальностью»: это цена одного дня. Для месячного бюджета
нужна скользящая средняя, иначе результат будет дёргаться при каждом заходе на
сайт. Это уже записано в `prix_carburants.caveat`.

## 4. Требование C — электромобили (главная новая работа)

Сегодня движок знает только термический двигатель: `litresPer100Km` × цена литра.
Для электромобиля это неприменимо целиком.

### 4.1 Что надо добавить на вход

| Поле                                      | Зачем                                      |
| ----------------------------------------- | ------------------------------------------ |
| Тип двигателя: `thermique` / `électrique` | Определяет, какая формула считает энергию  |
| `kwhPer100Km`                             | Расход ЭМ, аналог `litresPer100Km`         |
| Доля домашней зарядки vs публичной        | Это **два разных тарифа**, разница кратная |

### 4.2 Три ловушки, которые нельзя пропустить

1. **Двойной счёт электричества.** Домашняя зарядка — это тот же счёт за
   электричество, где уже стоит строка `electricite` (потребление жилья из
   Enedis). Если просто добавить «зарядку» отдельной строкой, часть киловатт
   посчитается дважды. Нужно решение: либо зарядка идёт **внутрь** строки
   `electricite` увеличением потребления, либо остаётся отдельной строкой, а
   в её `basis` прямо сказано, что она не входит в бытовое потребление.
   Первое честнее физически, второе понятнее пользователю. **Нужно решить.**

2. **`usage_vehicule` для ЭМ другой.** Строка сейчас берёт 0,15 €/км из
   национального барème kilométrique. У DGFiP для электромобилей барème
   применяется **с надбавкой** — точный коэффициент надо сверить с действующим
   текстом перед тем, как ставить цифру в код. Пока не сверено — ставить нельзя.

3. **Домашняя зарядка есть не у всех.** В квартире без парковки её просто нет, и
   тогда 100 % зарядки идёт по публичному тарифу. Это не деталь: разница между
   домашним и публичным тарифом больше, чем весь разрыв цен на бензин между
   городами. Значит вопрос про парковку/точку зарядки обязателен, иначе цифра
   будет вымышленной.

### 4.3 Что вышло в итоге (реализовано)

Вход: `VehicleInput { energy, litresPer100Km, kwhPer100Km, homeChargingShare }` —
машина принадлежит **домохозяйству**, а не поездке, потому что дорога на работу и
за покупками — это одна и та же машина. Гибридов в списке нет намеренно: DGFiP
считает их термическими, а честного публичного источника для их реального
разделения бензин/электричество не существует.

Строки на выходе (проверено в браузере, Dijon Centre-ville, 117 км/мес):

| Строка                        | Сумма | Статус       | Формула                          |
| ----------------------------- | ----- | ------------ | -------------------------------- |
| Recharge à domicile           | 3 €   | `CALCULÉ`    | 16 кВт·ч × 0,2016 €/кВт·ч        |
| Recharge sur bornes publiques | 2 €   | `HYPOTHÈSE`  | 4 кВт·ч × 0,45 €/кВт·ч           |
| Usage du véhicule             | 21 €  | `HYPOTHÈSE`  | 117 км × 0,18 €/км (0,15 + 20 %) |
| Installation d'une borne      | —     | `SANS OBJET` | разовая трата, не месячный поток |

Для сравнения, тот же пробег на бензине: 13 € топливо + 17 € усилие = 30 €,
против 26 € у электромобиля. Строка `Carburant` при `electrique` не выводится
вовсе — не нулём, а отсутствием.

**Как решены три ловушки из §4.2:**

1. Двойной счёт — выбран вариант «отдельная строка с оговоркой». В `basis` прямо
   сказано: «Ce montant s'ajoute à la ligne Électricité : la consommation du
   secteur ne tient pas compte d'un véhicule». Причина выбора: цифра Enedis —
   средняя по сектору, в котором электромобилей почти нет, поэтому вливать
   зарядку внутрь неё означало бы спрятать её от читателя.
2. Надбавка 20 % — **проверена**: arrêté du 16/02/2026, барème не
   переиндексирован с 2024, майорация 20 % применяется к итогу (×1,20) и только к
   100 % электрическим (гибриды и водород — нет). Но фискальная майорация
   **включает зарядку**, которую мы считаем отдельно, поэтому в строке написано,
   что мы применяем её к износу и амортизации как **гипотезу**, а не как
   налоговое правило. Это единственный корректный способ использовать это число,
   не занявшись двойным счётом молча.
3. Домашняя зарядка есть не у всех — спрашивается ползунком 0–100 %, по умолчанию
   80 %, с подсказкой «Sans place de parking, c'est 0 %». При 100 % строка
   публичной зарядки не выводится, при 0 % — не выводится домашняя.

Новый источник в реестре: `irve_bornes` (Base nationale des IRVE,
transport.data.gouv.fr, уровень `point`). Оговорка честная: тарифное поле в
консолидированном файле разнородно и часто пусто, поэтому цена публичной зарядки
остаётся гипотезой (0,45 €/кВт·ч), а не показанием.

### 4.4 Что в scope НЕ входит (и почему)

Bonus écologique, malus au poids, ZFE-ограничения, стоимость установки wallbox —
это разовые суммы и правила, а `reste à vivre` считает **месячный** поток.
Их место — отдельный симулятор «Coût réel de la voiture + ZFE» из
`docs/simulateurs-roadmap.md`, а не эта строка.

## 6. Юридические и эксплуатационные ограничения

Не формальность: эти три пункта могут обнулить работу, если всплывут после
запуска, а не до.

1. **Google Maps ToS.** Рейтинги, отзывы и фотографии Places нельзя хранить
   долгосрочно и нельзя показывать вне контекста Google-карты; Place ID
   кэшировать можно. Прежде чем закладывать эти данные в платный отчёт, надо
   прочитать действующие условия — иначе продукт строится на данных, которые нам
   не разрешено так использовать.
2. **Скрапер.** `gosom/google-maps-scraper` противоречит ToS Google. Пользователь
   сам ограничил его внутренним экспериментом — это правильная граница, и её
   нельзя размывать: ни одна цифра из скрапера не должна попасть в то, что
   видит клиент.
3. **Nominatim usage policy.** Публичный инстанс: не более 1 запроса в секунду,
   обязательный `User-Agent`, запрещён массовый геокодинг. Для ETL по всей
   Франции нужен **свой** инстанс. То же и для GraphHopper: бесплатный
   self-hosted или платный Directions API — это разные вещи, и «бесплатный
   маршрут» в таблице означает именно self-hosted.

## 7. Куда это ложится в архитектуру

Правило проекта (`STATWISE_PROJECT_PLAN.md` §2.2): **никаких живых обращений к
внешним API на пользовательский расчёт**. Движок обязан оставаться чистым — без
`fetch`, без `Date.now()`, детерминированным (это то, на чём стоят 69 тестов).

Отсюда граница:

```text
GraphHopper / OTP / Nominatim / Google
        ↓  (ETL или отдельный кешируемый route-сервис)
   snapshot.ts:  distanceToJobKm, distanceToGroceryKm, minutes
        ↓
   engine.ts  ←  чистая арифметика, ничего не знает о сети
```

То есть маршрутизация вызывается **на этапе подготовки данных** (или в отдельном
эндпоинте с кешем на адрес), а движок по-прежнему получает готовые километры.
Это же снимет баннер «Données d'amorçage», когда заглушки заменятся расчётом.

## 8. Открытые вопросы

Решено по ходу реализации:

- ~~Домашняя зарядка: вливать в `electricite` или отдельно?~~ → отдельной строкой
  с явной оговоркой (§4.3).
- ~~Тариф публичной зарядки: источник?~~ → `irve_bornes` как источник факта о
  бортах, но сама цена — `convention` 0,45 €/кВт·ч.
- ~~Гибриды: отдельный тип?~~ → нет, термические, и это сказано в интерфейсе.
- ~~Расход по умолчанию~~ → 17 кВт·ч/100 км, поле свободное.

Осталось решить:

1. **Радиус для медианы цены топлива:** сколько километров от жилья брать? Нужен
   до внедрения ETL prix-carburants.
2. **Адрес работы:** спрашивать точный адрес (тогда нужен геокодинг и встаёт
   вопрос приватности — см. `docs/privacy-scope.md`, где точный адрес жилья в V1
   намеренно **не** собирается) или оставить уровень квартала?
3. **Инстансы:** свой GraphHopper и Nominatim или платные API? От этого зависит,
   можно ли считать маршруты для всей Франции, или только для пилотных городов.

Пункт 2 — самый важный: он упирается в уже принятое решение о приватности, и
менять его надо осознанно, а не мимоходом.
